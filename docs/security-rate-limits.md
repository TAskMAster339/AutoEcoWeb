# Базовая защита AutoEco

Бесплатная конфигурация: защита сети у AdminVPS, ограничения Nginx и счётчики
PostgreSQL. Внешняя капча и платные сервисы не подключаются.

## Ограничения

| Операция | Ключ | Бюджет |
| --- | --- | --- |
| Все API-запросы | IP | 10/сек., burst 40 |
| Авторизация, дополнительно | IP | 30/мин., burst 20 |
| Одновременные API-запросы | IP | 20 |
| `/health` и `/health/ready`, общий бюджет | IP | 30/мин., burst 5 |
| Разбор и создание чека через внешний сервис, общий бюджет | пользователь | 10/мин. |
| Preview, import и export, общий бюджет | пользователь | 5/мин. |
| Создание обращения | пользователь | 3/10 мин. |

Существующие ограничения авторизации по IP/email сохраняются. Чтение сохранённых
чеков и ручное создание не расходуют бюджет внешнего сервиса. Общие ограничения
Nginx действуют и на эти запросы. Пользователи за одним NAT делят IP-бюджеты.

Nginx использует ограничение скорости с burst, backend — фиксированные окна,
начинающиеся с первой попытки. Неуспешные попытки также расходуют бюджет.
Превышение возвращает `429` с JSON `detail` и `Retry-After` в секундах.
У Nginx ожидание ориентировочное (5 секунд), у backend — до конца окна.
Frontend сохраняет форму и показывает ожидание, автоматически `429` не повторяет.
Сбой хранилища лимитов возвращает `503`, а не разрешает операцию.
Для счётчиков выделен отдельный небольшой пул (до 5 соединений на процесс),
чтобы запросы, уже занявшие основной пул БД, не блокировали проверку лимитов.

## Адрес клиента

Backend запускается с `--no-proxy-headers`: Uvicorn не подменяет TCP-адрес
клиента произвольными заголовками. Только для адресов доверенного прокси backend
читает `X-Real-IP`. Nginx всегда заменяет `X-Real-IP` и `X-Forwarded-For`.

Настройка `TRUSTED_PROXY_HOSTS` задаётся в корневом `.env`, значение по умолчанию
`nginx` соответствует имени сервиса Compose. Список имён/IP разделяется запятыми;
пустое значение отключает доверие заголовкам. DNS-адреса обновляются раз в минуту;
при ошибке разрешения доверие отключается. Не задавать публичные или чужие имена.
Backend и PostgreSQL не должны публиковаться в интернет; deploy compose уже
использует для них только внутренние порты. После замены контейнера Nginx
обновление доверенного IP может занять до минуты.

## Перед публикацией

1. В панели AdminVPS проверить наличие сетевой защиты именно у текущего VPS,
   её уровни, лимиты и условия блокировки IP при атаке. При необходимости
   самостоятельно уточнить это у поддержки. Код приложения не защищает от
   переполнения внешнего интернет-канала.
2. Проверить, что `APP_ENV=production`, HTTPS и существующие production-настройки
   авторизации сохранены. Для другой схемы проксирования настроить доверенные
   адреса отдельно; не доверять заголовкам произвольных клиентов.
3. Проверить конфигурацию `nginx -t` в deploy-контейнере с доступными сертификатами,
   пересобрать backend (изменены параметры Uvicorn) и перезапустить Nginx.
   Локальный dev-сервер не получает ограничения Nginx из deploy-конфигурации.
4. Проверить вход, импорт/экспорт, сканирование, ответы `429` и работу мониторинга.
   Внешние `/docs`, `/redoc`, `/openapi.json` возвращают `404`; для генерации типов
   используется прямой импорт приложения. Внутренние healthchecks сохраняются.

## Наблюдение и откат

Следить за `429`, `5xx` и временем ответов в логах Nginx/backend. Backend пишет
`rate_limit_exceeded action=...` и `rate_limit_unavailable action=...` без email,
токенов и паролей. При частых отказах обычным пользователям скорректировать
соответствующий бюджет. Просроченные счётчики старше суток очищаются порциями
до 1000 строк, не чаще одного раза в час на процесс при обработке запросов.

Откат: вернуть прежние версию приложения и конфигурацию Nginx, пересобрать backend
и перезапустить gateway. Миграций БД для этой функции нет. Настройки AdminVPS
управляются отдельно. Эта функция не заменяет аудит XSS, SQL-инъекций и зависимостей.
